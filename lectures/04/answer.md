## 演習

### 1. 実行条件

回答生成・採点モデルは`gemini-3.5-flash-lite`。採点のtemperatureは0、reason→verdictの順で出力する。採点モデルは回答モデルと同系統なので、独立性や正しさを保証できない。再実行でも完全に同じ判定になるとは限らない。

この端末では既存仮想環境の一部がクラウド退避されていたため、一時フォルダに`uv.lock`の固定バージョンを再構築した。SDKの既定httpx2経路で接続タイムアウトが出たため、`scripts/run_day04_eval.py`でproviderの公開`http_client`引数にhttpxを渡して実行した。SDK 2.57.0では対応しているが、v3で削除予定の非推奨経路であり、SDK更新時には見直す。採点条件は変えていない。混雑503で未完了となった試行は集計に使用せず、完了した再実行の結果だけ保存した。

### コード・LLM・人の使い分け

| 判定したいこと | 主な方法 | 理由・限界 |
|---|---|---|
| 回表示の書式、JSONの必須キー | コード | 決定的に確認できる。ただし今回の既存regexは入力例にも反応する |
| 引用した回番号が実在し適切か | コード＋LLM/人 | 存在はデータと照合できるが、回答との関連性は意味判断が必要 |
| 承認前・拒否後に保存がないか | ツールtrace＋実ファイル＋テスト | 「保存しません」という説明だけを採点しても状態の証拠にならない |
| 用語説明と参照の整合、宿題の完成解の提供 | LLM＋人の照合 | 言い換えを扱えるが観点の混同や見逃しがある |
| 簡潔さ・読みやすさ | LLMの案＋人 | 文字数制限はコード化できるが、必要十分かは内容による |
| 未決の境界、最終的な方針 | 人 | モデルの判定に合わせるのでなく、用途から方針を決める |

回表示の規則は今回は変更せず、比較の条件を固定した。次の改善案は「関係する回：第N回」の独立した最終行に出力形式を統一し、その形式と参照に照らして検査すること。ただし範囲外・曖昧入力・未知の回は「該当なし」を許すかも先に仕様化する。数字を合わせるために無関係な第N回を追加するのは避ける。

### 検証

- 自動テスト34件成功。第3回の承認・拒否・保存の検証に加えて、評価用生成でも拒否時に保存せず、文字列回答・trace・使用量が返ることをSDKのTestModelで確認した。
- TestModelの結果を実LLMの採点として使っていない。上の比較4回と独自10問の回答生成は実Geminiを使用した。
- コードの回表示では、Codex案でfailのケース5件のうち4件を検出、1件（#08）を見逃した。今回のラベル案に対する再現率は4/5。本人・専門家の正解に対する再現率とは呼べない。
- 根拠・範囲・ヒントは独自10問の案では全件passであり、これらの不合格検出能力は測れない。今後は意図的な誤回答も含めて検証する必要がある。

### 再現方法

APIキーは環境変数へ設定し、コードや公開ファイルへ書かない。

```bash
uv run python scripts/run_day04_eval.py --generate --cases data/eval/my_cases.jsonl --deny-approvals --trace-out lectures/04/verification/generation_trace.json
uv run python scripts/run_day04_eval.py --cases data/eval/my_cases.jsonl --labels lectures/04/my_labels_codex.jsonl --out lectures/04/my_judge_result.json --labeler Codexラベル案
uv run python scripts/run_day04_eval.py --cases data/eval/my_cases.jsonl --labels lectures/04/my_labels_codex.jsonl --rubric lectures/04/verification/rubric_before.md --out lectures/04/verification/my_before.json --labeler Codexラベル案
uv run python -m pytest -q
```

生成を再実行すると回答が上書きされ、旧ラベルと対応しなくなる可能性がある。まず保存済みの質問・回答・trace・判定理由を読む。本人がラベルを確認したら別名`lectures/04/my_labels.jsonl`に保存し、`--labels`をそのファイルへ変更して再採点する。

### 気づき・疑問

要確認が減るのは、回答モデルの改善とは別である。総合の一致が高くても、個々の基準での混同や形式判定の見逃しは残る。まず何を合格とするかを決め、判定方法の限界も一緒に報告することが大切だと考える。今後は本人のラベル確認、より多様な不合格例、独立した確認用セット、別モデルでの採点を追加したい。
