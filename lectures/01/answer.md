## 宿題

- 取り組んだレベル：実装
- やったこと：
  - `app/ask.py` に `--chat` オプションを追加した。
  - `client.chats.create(model=MODEL)` で生成した同じChatを使い続け、`send_message()` で質問することで、ユーザーの質問とモデルの回答を次の質問に引き継ぐ。
  - `/reset` で新しいChatを作成し、`/exit`・EOF・Ctrl+Cで終了できるようにした。空入力は送信しない。
  - 従来の `ask(question)` と単発実行を維持した。
  - 演習のトークン数表示を実装した。`usage_metadata.prompt_token_count` と `candidates_token_count` を標準エラー出力に表示し、値がない場合は「不明」とする。実際に0なら0と表示する。
  - APIエラーを日本語で表示し、対話中は次の入力を受け付けるようにした。
- 結果：
  - Python 3.12.14、google-genai 2.31.0で、通信部分だけテスト用応答に置き換えて検証した。
  - 2回目のAPI呼び出しに「最初の質問・最初の回答・次の質問」の順で履歴が渡ることを、実際のSDKのChatを使って確認した。
  - `/reset` 後は以前の履歴が渡らず、APIエラーになった質問も次の履歴に混入しないことを確認した。
  - 追加テスト12件と既存テスト11件の合計23件が成功した。詳細は同梱の検証記録を参照。
  - 実際のGemini APIへの問い合わせ、回答品質、実トークン数、Codespaces上の動作は未検証。
- 使ったモデル：実APIは未実行のため、使用モデルはなし。実行時の既定値は講座の `app/config.py` の `gemini-3.5-flash-lite` を維持している。`AIE_MODEL` で変更できる。提出前に実行したモデル名を追記する。
- 気づき・疑問：
  - 会話履歴の保持は、過去の会話を次の入力に含める仕組みであり、モデルの追加学習とは異なる。
  - 会話が長くなると、毎回渡す履歴も増える。入力トークン数や応答時間・コストの増加、コンテキスト上限への対応として、履歴の要約や制限を検討する必要がある。
  - 履歴があっても、講座固有の事実を知らないという問題は残る。資料の検索や根拠の提示は、別途設計する必要がある。
  - 現状の履歴は実行中のメモリだけに保持し、終了後に復元しない。
